/ 03 — execution policy

Your shell.
Your call.

Shell commands can change your machine. dum-tum takes a conservative route: local read-only corrections can be automatic; AI output always waits for you.

Read the complete safety notes ↗
execution_rules.txtread-only overview
local.safe_correctionmay auto-run
local.other_correctionask first
ai.suggestionalways ask first
provider.noneoffline typo handling

AI mode sends your request and selected shell context to the provider. With AI configured, eligible failed commands are also sent automatically by default (FX_AI_ON_FAIL=1). Set FX_AI_ON_FAIL=0 to disable those automatic requests. Review the privacy details if you work with sensitive data.

01 / ENTRYPOINT

The npm command starts Bash.

npx fetches the dum-tum package. Its small Node entrypoint runs the bundled install.sh.

$ npx dum-tum@latest→ npm package: dum-tum→ bin/dum-tum.js → bash install.sh

You can also run the Bash installer without Node. See the installation guide below.

02 / PREFLIGHT

It checks your shell and tools.

The installer selects your login shell, checks its config file, and checks for Python 3, curl, and zsh when needed.

✓ choose zsh, Bash, or both✓ check existing shell config? install missing tools when supported

If tools are missing, it can use Homebrew, apt, dnf, or pacman. The package manager may ask for permission or a sudo password.

03 / RUNTIME

It stages and checks the files.

The installer copies the shell adapters and helper files to a temporary folder. It validates them before it moves them into the install folder.

→ temporary install folder├ shell adapters + shared helper└ Python AI helper → validate

The default install folder is ~/.local/share/fixit. That internal folder name remains for compatibility.

04 / OPTIONS

You choose how AI works.

The installer looks for supported AI CLIs. You can pick one, use an API provider, or choose none for local typo fixes only.

? provider: CLI / API / none? model: provider default or your choice✓ optional provider smoke test

API keys use a hidden prompt. A key you enter can be saved in your shell config, which the installer protects with file mode 600.

05 / SHELL CONFIG

It adds one managed config block.

The installer installs the staged files and adds a block that loads the adapter in ~/.zshrc or ~/.bashrc.

→ ~/.local/share/fixit/→ ~/.zshrc or ~/.bashrc✓ source adapter + provider settings

On an update, it replaces the existing managed block. If activation fails, it attempts to restore the previous files.

06 / ACTIVATE

Reload your shell and try it.

Open a new terminal tab or source the config file shown by the installer. Then the hook can see what you enter.

$ source ~/.zshrc$ sl → local correction$ list all files → AI suggestion if enabled

If you chose Bash, source ~/.bashrc instead. AI suggestions always wait for you to run, edit, or cancel them.

/ 06 — FAQ

Good to know.

More in the README ↗

Does dum-tum run AI commands automatically?

No. AI suggestions always wait for you to press Enter to run, e to edit, or n to cancel. Some safe, read-only typo corrections can run locally without AI.

Do I need an API key?

No. You can use local-only typo handling, or use a supported CLI you already have installed and authenticated. Key-based AI providers are optional.

Which shells and systems work?

dum-tum supports zsh 5+ and Bash 4+ on macOS and Linux. macOS's bundled Bash 3.2 supports local typo handling, but needs a newer Bash or zsh for the full Enter hook.

What does AI mode send?

AI mode sends your request plus shell context such as your OS, current directory, some directory entries, aliases, and project commands. Read the safety notes before using AI with sensitive work.
